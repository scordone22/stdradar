给一个标准号，判定它在你库里是**现行 / 已过期 / 过渡期 / 已废止**，并给出唯一处置动作。

解决的是一个具体而普遍的麻烦：企业的标准清单里混着作废版本，投标、审查、体系审核时被挑出来，往往已经是最后关头。查一遍要人工一个个点官网，几百个标准就是几天工作量。

```bash
pip install stdradar

$ stdradar normalize "GB50014—2021"
'GB50014—2021'   ->  GB 50014-2021  家族=GB 50014

$ stdradar judge "GB 50014-2006" --latest "GB 50014-2021" --status 现行 --implement 2022-01-01
库内  : GB 50014-2006
官方  : GB 50014-2021
判定  : 过期  (outdated)
依据  : 新版 GB 50014-2021 已实施（2022-01-01）
处置  : 旧版移入「已废止版本」目录并注明取代依据；新版归档到现行目录。
```

离线批量体检，直接跑仓库里的示例清单：

## 为什么不是「比年号大小」

凡是写过年号比较的人都会踩这三个坑，库里每一个 false positive 都从这儿来：

**1. 模糊检索会造假警报。** 官方平台按标准号模糊匹配，搜 `GB 3838` 会返回 `GB 38383`（洗碗机能效）。取首行当最新版，就会给一条本来没问题的标准打上「已过期」。本库先按**完整主号**建族校验，跨族结果直接判 `mismatch` 丢弃。

**2. 分部分标准不是替代关系。** `GB 16171.1-2024` 与 `GB 16171-2012` 并存，且两件均现行。编号前缀相同、年号更新，都不构成替代。本库对「一方带分部分号、一方不带」的情况判 `part_parallel`，替代关系只认公告里的「全部代替」字段。

**3. 查不到 ≠ 废止。** 工程建设标准（GB 50xxx/51xxx/55xxx）与行业标准（HJ/CJ/CJJ/SL）**不在**国家标准全文公开系统收录范围。搜不到只能返回 `unknown`，绝不判废止——这条错了会把有效标准整批下架。

## 四类判定

判定不看年号单独定，而是 **年号 + 官方状态 + 实施日期** 三者合成：

| 情形 | 判定 | 处置 |
|---|---|---|
| 同年号，状态现行 | `current` | 不动 |
| 库内更旧，新版**已实施** | `outdated` | 旧版归档，新版归位 |
| 库内更旧，新版**已发布未实施** | `transition` | 新旧并行，旧版仍在效，到期日后再归档 |
| 同年号，状态废止 | `abolished` | 归档，注明「复审废止，无替代」 |

`transition` 带 `deadline`，直接给出到期日，方便定点清理而不是每季度重查一遍。

批处理：

```bash
# CSV 列：code,latest,status,implement_date
$ stdradar check 标准清单.csv --out 体检报告.md
```

输出 Markdown 表格与计数，可直接贴进汇报。

## 状态不一致时信谁

实施日期优先于状态字段。平台状态存在滞后（新版已实施但状态仍是「即将实施」），本库在 `status=现行` 但 `implement_date > today` 时仍判 `transition`。反过来，库内年号**高于**官方返回值时判 `inconsistent`，这基本意味着查到了同号其它标准，不要机械执行归档。

## 范围与边界

- **只做判定，不做条文。** 本库不含标准正文、不含条文库，不提供全文下载。
- **数据来源是官方公开查询接口**，仅做只读检索；请遵守站点条款，不要高频批量抓取（内置 0.3s 间隔与页数上限）。
- **不构成合规结论。** 最终以官方发布公告与正式文本为准；本工具的价值是把人工点查的时间压下来，并避免三类系统性误判。

- [x] 标准号归一（全角/破折号/两位年号/分部分）

- [x] 官方查询接口解析与批量体检

## 许可

Apache-2.0。核心判定逻辑永久开源；条文库、行业审查规则包、批量托管体检服务不在本仓库内。

Contributions welcome — 遇到误判请附上标准号与官方页面，这类 issue 最有价值。
